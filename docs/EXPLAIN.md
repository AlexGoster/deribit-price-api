# Как показать и объяснить проект

Сначала самостоятельно запусти приложение и пройди примеры из README.
Объясняй только то, что действительно понимаешь; использование помощника не
заменяет понимание кода. Если спрашивают об инструментах разработки, отвечай честно.

## Демонстрация на пять минут

1. Покажи README и `docker compose ps`: отдельно приложение, отдельно PostgreSQL.
2. Открой `/docs`. Выполни `GET /prices` с `ticker=btc_usd`; покажи поля записи.
3. Выполни `/prices/latest` для `eth_usd`. Объясни, что это сохранённая цена,
   а не прямой запрос к бирже.
4. Выполни `/prices/by-date` для текущей даты UTC. Убери ticker — получишь 422.
5. Подожди минуту и запроси историю снова: количество записей увеличится,
   если биржа доступна. Покажи сообщения сборщика в логах.
6. Покажи результаты тестов и один тест границ суток. Заверши объяснением
   ограничения: один worker, иначе каждый запустит свой сборщик.

## Путь данных

`create_app` читает настройки → lifespan открывает БД и aiohttp-сессию →
`PriceCollector.run` начинает цикл → `DeribitClient.get_index_price` запрашивает
индекс → клиент проверяет ответ → repository сохраняет Decimal и время →
HTTP-запрос попадает в роут → repository выбирает записи → Pydantic формирует JSON.

## Частые вопросы

**Почему async?** Ожидание сети или БД не должно блокировать обработку других
запросов. `await` отдаёт управление event loop. Это не ускоряет вычисления CPU.

**Что такое задача asyncio?** `create_task` запускает coroutine сборщика вместе
с обслуживанием HTTP. Это одна задача в том же процессе, отдельного worker нет.

**Зачем монотонные часы и UNIX время одновременно?** Монотонные часы измеряют
интервалы и не зависят от перевода системных часов. UNIX timestamp описывает
реальный момент наблюдения и нужен для хранения и фильтра по датам.

**Почему Decimal?** Десятичные дроби нельзя всегда точно представить двоичным
float. JSON разбирается с parse_float=Decimal, PostgreSQL хранит NUMERIC.
В JSON ответа цена — строка, чтобы клиент тоже мог сохранить точность.

**Почему новая сессия для операции?** AsyncSession нельзя безопасно делить
между одновременно выполняющимися запросами. Session factory создаёт короткие
сессии, engine управляет пулом соединений.

**Что делает транзакция?** Либо запись сохраняется целиком, либо при ошибке
операция откатывается. `async with session.begin()` управляет commit/rollback.

**Почему Depends?** Роут получает repository из приложения, а не создаёт
соединение сам. Это упрощает замену зависимости и проверку HTTP-контракта.

**Что произойдёт при сбое биржи?** Ограниченные повторы для временных ошибок,
затем логирование. Второй тикер продолжит сбор, следующий цикл снова попробует.
Никакая выдуманная цена не записывается. Старые записи доступны.

**Что произойдёт при сбое БД?** Запись текущего наблюдения потеряется, ошибка
попадёт в логи, последующие циклы попробуют снова. Долговечной очереди нет.
API вернёт 503, если запрос к БД не удался. При недоступной БД во время запуска
приложение не стартует; Compose ждёт готовности БД и перезапускает сервис.

**Зачем индекс?** Поиск сначала ограничивается ticker, затем временем.
Составной индекс соответствует фильтрации и сортировке. Это помогает БД
не сканировать всю таблицу при запросе последней цены или дня.

**Что улучшить для production?** Миграции, отдельный процесс сборщика,
пагинация/retention, мониторинг свежести данных, резервные копии,
лимиты API и HTTPS. Не заявляй, что всё это уже реализовано.

## Подготовка

Прочитай файлы в порядке: schemas → models → repository → client → collector →
main → api. Попробуй поменять интервал на 10 секунд в своём `.env`, перезапустить
приложение и увидеть изменение. Затем верни 60 секунд. Объясни своими словами,
почему фильтр дня использует `<` для следующей полуночи, а не `<=`.
